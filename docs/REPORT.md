# UX standard delivery: CI and payload

The workspace's existing engine looks for `playwright` in the project, `NODE_PATH`, and npm's global root, including `@playwright/mcp/node_modules/playwright`. This uses the browser gate's existing MCP installation and its Chromium instead of installing a second Playwright version. The upstream delivery must preserve that nested lookup. The workflow and its pin test remain unchanged. The current `tests/lane_durations.json` already records the UX test files in the per-lane format.

The existing standards encoder accepts up to 96,000 encoded bytes and limits uncompressed files to 512,000 bytes; its decoder enforces the same limits. The upstream delivery must preserve that 96,000-byte limit: the upstream 48 KB limit rejected the complete standard. The deployment regression copies the shipped standards into a workspace, selects UX, round-trips the deployment profile, verifies every check script and its contents, and checks the resulting environment string against Linux's 128 KiB per-string limit. In this workspace the selected standard encodes to 82,900 bytes. This leaves room for a normal profile, but unusually large profiles or standards still fail the existing limits.

The slot's global installation contains `@playwright/mcp` 0.0.83 and its nested `playwright` 1.64.0-alpha-1790635538000, matching upstream CI. With `NODE_PATH` unset and no top-level global Playwright, `PYTHONPATH=src uv run python -m pytest tests/test_ux_checks_render.py -q -n 4` passed all 112 tests, including the new lookup regression and the missing-Playwright failure test. The implementation and lane entries already existed in the workspace branch, so these regression tests do not change production behaviour relative to that branch.
